# GD32F150 — Карта заліза та розпіновка (реверс-інжиніринг заводської прошивки)

**Джерело:** статичний аналіз `tools/swd/gd32_flash.bin` (64 КБ, Cortex-M3 Thumb-2) — скан базових адрес периферії + дизасемблер (capstone).
**Призначення:** довідник для написання власного GD32-драйвера під **реальні** піни/протоколи. Доповнює [`CUSTOM_FIRMWARE_SPEC.md`](CUSTOM_FIRMWARE_SPEC.md) (§2, §4.2).
**Статус:** дисплей — витягнуто повністю; решта — частково (див. §6 «Що ще витягти»).

---

## 1. Інвентар периферії (скан базових адрес у дампі)

| Блок | База | Задіяно | Роль |
|---|---|---|---|
| **USART0** | `0x40013800` | ✅ | CO₂-сенсор (CRIR M1, Modbus) — див. §3 |
| **USART1** | `0x40004400` | ✅ | Лінк з ESP32 (PA2/PA3, 115200) |
| **GPIOB** | `0x48000400` | ✅ (рясно) | Дисплей (бітбенг), інше I/O |
| **GPIOA/C/F** | — | ✅ | I/O (LED/кнопка/сенсори — уточнюється) |
| **TIMER0/2/5/13/14/15/16** | — | ✅ | PWM (підсвітка, зумер), таймінги |
| **FWDGT (IWDG)** | `0x40003000` | ✅ | Незалежний watchdog — **підтверджує здійсненність §9.3** |
| **RCU / RTC / PMU / EXTI** | — | ✅ | Клоки/живлення/переривання |
| **SPI0 / SPI1** | `0x40013000` / `0x40003800` | ❌ **не задіяно** | Дисплей іде **бітбенгом**, не HW-SPI |
| **I2C0 / I2C1** | `0x40005400` / `0x40005800` | ❌ **не задіяно** | SHT30 іде **бітбенгом** |
| **ADC** | `0x40012400` | ✅ | Напруга батареї — `ADC_IN9` (`PB1`) — див. §6.7 |

**Наслідок:** заводська прошивка не використовує апаратних SPI/I2C — дисплей і SHT30 бітбенгаються по GPIO. Для нас це не блокер (вузьке місце — UART-канал до ESP32).

## 2. Дисплей ST7789 (240×240) — ПОВНІСТЮ ВИТЯГНУТО

### 2.1. Розпіновка (GPIOB, бітбенг, 3-дротовий 9-бітний serial)
Заводська прошивка керує дисплеєм у **3-line (9-bit) SPI** режимі: біт D/C передається як 9-й (перший) біт перед 8 бітами даних, окремого DC-піна не використано.

| Сигнал | Пін GD32 | Примітка |
|---|---|---|
| **SCK** (clock) | **`PB13`** | тактується щобіта (set-low → delay → set-high) |
| **CS** (chip select) | **`PB14`** | активний LOW; опускається на старті кадру байта |
| **SDA/MOSI** (data) | **`PB15`** | значення на кожен біт; для команди 9-й біт=0, для даних=1 |
| **RES** (reset) | **`PB12`** | окремий тогл у hw-init `0x080043E8` (reset-пульс перед init) |
| Backlight (PWM) | **`PB8`** | TIMER15_CH0 (AF2); 100% верифіковано на залізі (HIGH = ON, PWM яскравість) |

> **Важливо для §4.2:** `PB13`/`PB15` збігаються з **`SPI1_SCK`/`SPI1_MOSI`** (апаратний SPI1: NSS=PB12, SCK=PB13, MISO=PB14, MOSI=PB15). Тобто **апаратний SPI1+DMA для пікселів цілком реальний** — треба лише вирішити 9-біт framing або задіяти фізичний DC-пін (якщо він розведений на FPC) для класичного 4-wire.

### 2.2. Low-level функції (адреси в дампі)
| Функція | Адреса | Опис |
|---|---|---|
| `write_command(u8)` | `0x080052F0` | CS↓, D/C=0 (9-й біт), тактує байт |
| `write_data(u8)` | `0x080051CA` | CS↓, D/C=1 (9-й біт), тактує байт |
| `set_window+blit` | `0x080045B4` | CASET/RASET/RAMWR + потік пікселів |
| `bit_delay` | `0x08005044` | коротка затримка такту |
| sleep in/out | `0x0800512C` (SLPOUT `0x11`), `0x08005164` (SLPIN `0x10`) | вкл/викл дисплея |

### 2.3. Заводська init-послідовність (перевірена, копіювати як є)
Регістр : аргументи (hex):
```
01                      SWRESET
11                      SLPOUT
B2  1F 1F 00 33 33      PORCTRL (порчі)
35  00                  TEON (tearing effect on)
36  00                  MADCTL  → орієнтація за замовч., RGB, без mirror/flip
3A  05                  COLMOD  → 16 біт/піксель (RGB565)
B7  02                  GCTRL
BB  31                  VCOMS
C0  2C                  LCMCTRL
C2  01                  VDVVRHEN
C3  19                  VRHS
C4  20                  VDVS
C6  13                  FRCTRL2 (частота кадрів)
D0  A4 A1               PWCTRL1
D6  A1                  (vendor)
E0  F0 04 0A 09 0A 27 2C 43 42 38 13 13 27 2B   PVGAMCTRL (позитивна гамма)
E1  F0 05 08 0A 08 04 2C 43 41 3A 16 16 28 2C   NVGAMCTRL (негативна гамма)
E4  1D 00 00            (gate/vendor)
21                      INVON (інверсія — норма для IPS ST7789)
3A  ...                 COLMOD (повтор) + перше вікно
29                      DISPON (дисплей увімкнено)
```
> `MADCTL=0x00` + стандартна 240×240 панель → зсуви вікна беруться зі структури кадру (поля x0/x1/y0/y1 у set_window `0x45B4`); базовий зсув для цієї панелі підтвердити на бенчі (типово (0,0)).

## 3. CO₂-сенсор — Honeywell CRIR M1 (ПОВНІСТЮ ВЕРИФІКОВАНО НА ЗАЛІЗІ)

* **Інтерфейс:** апаратний **USART0** (`0x40013800`):
  * **`PA9`** — **USART0 TX** (AF1, Push-Pull, 50MHz, Pull-Up) → нога 3 сенсора `UART_RXD`.
  * **`PA10`** — **USART0 RX** (AF1, Pull-Up) ← нога 4 сенсора `UART_TXD`.
  * **Параметри зв'язку:** **9600 бод, 8N1** (`USART0_BAUD = 0x0341` при 8 МГц).
* **Керування живленням сенсора:**
  * **`PB11`** — **5V Boost DC-DC Enable** (Active-HIGH). Вмикає підвищувальний перетворювач 5V, необхідний для роботи NDIR інфрачервоної лампи сенсора (пікове споживання до 300 мА).
  * **`PB9`** — **Sensor Power / Rail Switch** (Active-HIGH). У заводській прошивці (`0x080038A4`, `0x0800BB1A`, `0x0800C0B0`) виставляється в `1` під час активної роботи і в `0` під час сну. Без `PB9=1` сенсор знеструмлений.
* **Протокол (Modbus RTU):**
  * **Запит концентрації CO₂** (Cmd #0 із заводської таблиці `0x0800F00C`):
    ```text
    FE 04 00 07 00 01 94 04
    ```
    * `FE` — Slave address / broadcast.
    * `04` — Read Input Registers.
    * `00 07` — Input Register 7 (CO₂ concentration).
    * `00 01` — 1 регістр (16 біт).
    * `94 04` — CRC-16 Modbus (little-endian).
  * **Відповідь сенсора (7 байт):**
    ```text
    FE 04 02 [High] [Low] [CRC_L] [CRC_H]
    ```
    `CO2 (ppm) = (High << 8) | Low`.
* **Верифікація на залізі:** **100% підтверджено**. Тестовий інструмент ([`./tools/bench.py co2`](file:///home/max/pet/ha-htram/tools/bench.py)) стабільно читає дані сенсора:
  ```text
  [CO2] Pin diagnostics: PA9(TX)=1, PA10(RX)=1, PB9=1, PB11=1
  [CO2] Waiting 2s for CRIR M1 NDIR power-up...
  [CO2] After 2s: PA10(RX)=1, USART0_STAT=0x00F8
  [#1] CO2: 0 ppm    |  Temp: 29.3 C  |  Humidity: 38.7 %RH
  [#2] CO2: 533 ppm  |  Temp: 29.3 C  |  Humidity: 38.6 %RH
  [#4] CO2: 584 ppm  |  Temp: 29.3 C  |  Humidity: 38.3 %RH
  [#6] CO2: 630 ppm  |  Temp: 29.3 C  |  Humidity: 38.2 %RH
  [#8] CO2: 704 ppm  |  Temp: 29.4 C  |  Humidity: 41.8 %RH
  ```
  *(Зростання CO₂ з 533 до 704 ppm та вологості з 38% до 42% зафіксовано при видиху поруч із приладом).*
* Даташит: [`../CO2_CRIR_M1.pdf`](../CO2_CRIR_M1.pdf).

## 5. T/H — Sensirion SHT30 (ПОВНІСТЮ ВЕРИФІКОВАНО НА ЗАЛІЗІ)

* **Шина I2C:** бітбенг I2C по GPIO:
  * **`PB6`** — **SCL** (Output Open-Drain з підтяжкою).
  * **`PB7`** — **SDA** (перемикається між Output Open-Drain для передачі та Input для зчитування бітів/ACK).
* **Керуючі піни сенсора:**
  * **`PA8`** — **SHT30 `nRESET`** (Active-LOW). Під час ініціалізації короткочасно притискається до 0 (10 мс) і повертається в HIGH (1) / float. Без підняття цієї лінії сенсор залишається у стані апаратного скидання.
  * **`PB2`** — Ініціалізується у заводській прошивці (`0x0800C2B8`) як Output Push-Pull з підтяжкою і виставляється в `HIGH`. **Але живлення SHT30 він НЕ гейтить** — спростовано на залізі ([`tools/swd/battery_test.c`](../tools/swd/battery_test.c), тест 1): при `PB2=0` сенсор і далі віддає валідні покази з правильним CRC, ідентичні до `PB2=1` (31.93 °C проти 31.94 °C). Дільник батареї він теж не комутує (§6.7). У даташиті в `PB2` взагалі немає аналогової функції — лише GPIO / `TSI_G2_IO3`. Тримаємо його `HIGH` як у заводській прошивці й не смикаємо.
* **I2C адреса:** **`0x44`** (Write `0x88`, Read `0x89`). Скан 0x08..0x77 підтверджує відгук ACK виключно на `0x44`.
* **Підтримувані протоколи читання:**
  * **Періодичний режим із прискореним опитуванням (ART):** старт командою `0x2B32`, зчитування 6 байт командою `0xE000` (заводський метод).
  * **Одиночний замір (Single-shot):** команда `0x2400` (High repeatability, no clock stretching) з паузою ~15 мс і читанням 6 байт.
* **Перевірка цілісності:** контрольна сума **CRC-8** (поліном `0x31`, ініт `0xFF`). Окремо для 2 байт температури та 2 байт вологості.
* **Верифікація на залізі:** **100% підтверджено**. Тестовий інструмент ([`./tools/bench.py temp`](file:///home/max/pet/ha-htram/tools/bench.py)) стабільно зчитує валідні покази з коректним CRC:
  ```text
  [I2C] Scanning I2C bus (addresses 0x08..0x77)...
    -> [I2C] ACK received at 7-bit addr: 0x44
  [I2C] Sending Periodic ART Start Command (0x2B32) to 0x44...
    -> Results: addr_ack=1, msb_ack=1, lsb_ack=1
  [#1] Temp: 29.0 C  |  Humidity: 39.0 %RH  |  [Periodic] OK
  [#2] Temp: 28.9 C  |  Humidity: 39.0 %RH  |  [Periodic] OK
  ```

## 6. Індикація, зумер, кнопка, живлення (ПОВНІСТЮ ВЕРИФІКОВАНО)

### 6.1. Світлодіоди світлофора (дуга з 5 LED)
Фізично на платі розташовано 5 світлодіодів у формі дуги (`LED06`, `LED04`, `LED05`, `LED07`, `LED03`), згрупованих за 3 рівнями ризику:
* **`PC14`** — **2 Зелені світлодіоди** (Низький ризик / Low risk).
* **`PB4`**  — **1 Помаранчевий/жовтий світлодіод** (Середній ризик / Medium risk).
* **`PB5`**  — **2 Червоні світлодіоди** (Високий ризик / High risk).
* **Полярність:** Active-HIGH (HIGH = увімкнено, транзисторні ключі NPN/N-FET).
* **Живлення VLED:** аноди світлодіодів живляться через P-MOSFET ключ, керований лінією **`PA1`** (HIGH = живлення подано). Без `PA1=1` діоди не світяться.

### 6.2. Кнопка `SW1` (передньої панелі)
* **Пін:** **`PA0`** (вхід без внутрішньої підтяжки, підтягнутий на платі до GND).
* **Полярність:** **Active-HIGH** (`1` = натиснуто, `0` = відпущено).
* **Верифікація:** перевірено на живому залізі через SWD SRAM-інструмент ([`./tools/bench.py leds`](file:///home/max/pet/ha-htram/tools/bench.py)). Реєстрація кліків працює чітко без брязкоту.

### 6.3. Зовнішня SPI Flash / EEPROM
* **Шина:** бітбенг SPI на порту A:
  * **`PA4`** — CS (Chip Select, active-LOW)
  * **`PA5`** — SCK (Serial Clock)
  * **`PA6`** — MISO (Serial Data In / Input)
  * **`PA7`** — MOSI (Serial Data Out / Output)
* У заводській прошивці ініціалізується функцією `0x080006D6`, звертається стандартними SPI-інструкціями (`0x06` WREN, читання/запис 24-бітних адрес).

### 6.4. Зумер `LS1` (Buzzer)
* **Пін:** **`PB0`**
* **Керування:** PWM через **`TIMER2_CH2`** (AF1).
* **Резонансна частота:** **2304 Гц** (Prescaler=71, Period=434 у заводській прошивці `0x08004080`).
* **Верифікація:** **100% підтверджено на залізі** (видає чіткий звук на частотах 1кГц–4кГц, відгукується на клік кнопки).

### 6.5. Підсвічування дисплея (Backlight)
* **Пін:** **`PB8`**
* **Керування:** PWM регулювання яскравості через **`TIMER15_CH0`** (AF2) або постійний рівень `HIGH` (увімкнено).
* **Верифікація:** **100% підтверджено на залізі** (екран підсвічується стабільно при `PB8=HIGH`).

### 6.7. Вимір напруги батареї (ВЕРИФІКОВАНО)
* **Канал:** **`ADC_IN9`** на піні **`PB1`** (звірено з таблицею пінів даташита GD32F150xx).
* **Формула:** `mV = (raw * 3275) >> 11`. Перевірено на залізі: `raw=2588` → **4138 мВ**, тоді як референсний пристрій на заводській прошивці віддає в MQTT-телеметрії **4143 мВ**.
* **Альтернативний розрахунок** через внутрішній Vrefint (`ADC_IN17`, 1.2 В) дає VDDA = 3304 мВ і, за номінального дільника 2:1, 4176 мВ — на ~40 мВ вище. Тобто заводська константа точніша за номінал; лишаємо її.
* **Дільник нічим не комутується** — жодний GPIO не впливає на покази каналу 9 (перевірено скануванням усіх 18 каналів при `PB2=1` і `PB2=0`).
* **Тригер АЦП:** треба `ETSRC=0b111` + `ETERC`, і лише тоді `SWRCST`. Сам по собі `SWRCST` не виставив `EOC` на першій конверсії після калібрування.
* **Внутрішній термодатчик** (`ADC_IN16`, `V25=1.45 В`, 4.1 мВ/°C) показав ~43 °C кристала — саме тому SHT30 на платі читає помітно вище за кімнатну температуру.

### 6.6. Керування живленням / Power Rails
* **`PC15`** — **Головний Power Latch / DC-DC enable** (Output PP, HIGH = утримання живлення системи).
* **`PB3`**  — **Peripheral Power enable** (Output PP, HIGH = живлення периферії).
* **`PA1`**  — **VLED Switch enable** (Output PP, HIGH = живлення анодів світлодіодів).

## 7. Що ще витягти / перевірити

- [x] **LED колір→пін** — **100% ВЕРИФІКОВАНО**: `PC14` (2 зелені), `PB4` (1 помаранчевий), `PB5` (2 червоні).
- [x] **Кнопка `SW1`** — **100% ВЕРИФІКОВАНО**: `PA0` (Active-HIGH).
- [x] **Power Rails / Latch** — **100% ВЕРИФІКОВАНО**: `PC15` (SYS), `PB3` (PERIPH), `PA1` (VLED).
- [x] **Зовнішня SPI Flash** — **100% ВЕРИФІКОВАНО**: `PA4` (CS), `PA5` (SCK), `PA6` (MISO), `PA7` (MOSI).
- [x] **Backlight** — **100% ВЕРИФІКОВАНО**: `PB8` (TIMER15_CH0 / HIGH = ON).
- [x] **Зумер** — **100% ВЕРИФІКОВАНО**: `PB0` (TIMER2_CH2, 2.3 kHz).
- [x] **SHT30 I2C (T/H)** — **100% ВЕРИФІКОВАНО**: `PB6` (SCL), `PB7` (SDA), `PA8` (nRESET). Опитування 0x44 (ART / Periodic 0xE000). `PB2` — **не** живлення сенсора (§5).
- [x] **Батарея** — **100% ВЕРИФІКОВАНО**: `ADC_IN9` на `PB1`, формула `(raw*3275)>>11` (§6.7).
- [x] **USB / заряд** — **ВЕРИФІКОВАНО в обох станах**: на акумуляторі `PC13=0` → Status `[]`; із підключеним живленням `PC13=1` → Status `[Charging, USB]`. `PA15` — статус зарядника, значущий лише за наявності VBUS.
- [x] **CO₂ USART0** — **100% ВЕРИФІКОВАНО**: `PA9` (TX), `PA10` (RX) @ 9600 бод, `PB11` (5V Boost), `PB9` (Power Switch). Modbus Cmd #0 `FE 04 00 07 00 01 94 04`.
- [x] **ST7789 Дисплей** — **100% ВЕРИФІКОВАНО**: `PB12` (RES), `PB13` (SCK), `PB14` (CS), `PB15` (SDA), `PB8` (Backlight). 3-wire 9-bit SPI bitbang, 240×240 RGB565.
